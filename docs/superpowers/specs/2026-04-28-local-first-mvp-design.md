# 山海映记本地优先 MVP 设计

日期：2026-04-28

## 背景

山海映记已经是一个可运行、可展示的静态移动端旅行影像档案原型。当前版本包含档案首页、全部映记、映记详情、社区点评、目的地详情、创建映记、本地保存和分享长图导出。

下一阶段目标不是继续堆页面，而是把它变成一个真正能长期使用的本地优先个人旅行档案工具。它应当在没有账号、后端和云同步的前提下，让用户能放心记录、检索、备份和恢复自己的旅行映记。

## 目标

1. 保持无后端、可直接打开的静态应用形态。
2. 让用户创建的映记具备稳定数据结构，可导出、可恢复、可迁移。
3. 把当前单文件脚本拆成可理解、可测试的模块边界。
4. 增强档案管理能力：编辑、删除、收藏、标签、年份/城市筛选。
5. 保持当前视觉体验和已有交互，不做大改版。
6. 让测试从“结构存在”升级到“关键用户流程可回归”。

## 非目标

1. 不引入账号系统、后端服务或云同步。
2. 不接入真实地图 SDK、社交分享 API 或支付能力。
3. 不重写为 React/Vue/Next.js。
4. 不把原型改成营销落地页。
5. 不新增依赖，除非为了标准化测试运行确实需要最小项目元数据。

## 推荐架构

保留静态前端，但把 JavaScript 从一个大文件拆成职责明确的模块。

```text
src/
├── main.js
├── data/
│   ├── seed-destinations.js
│   └── seed-memories.js
├── domain/
│   ├── memory.js
│   └── archive.js
├── storage/
│   ├── local-store.js
│   └── archive-export.js
├── ui/
│   ├── router.js
│   ├── archive-view.js
│   ├── create-view.js
│   ├── destination-view.js
│   └── poster-view.js
└── utils/
    ├── file.js
    └── dom.js
```

`main.js` 只负责启动：读取 DOM、初始化存储、注册事件、渲染首屏。

`domain/` 负责纯数据逻辑，例如映记结构校验、筛选、排序、派生统计。

`storage/` 负责 `localStorage` 读写、版本迁移、导入导出。

`ui/` 负责 DOM 渲染和交互绑定，不直接拼业务规则。

## 用户流程

### 创建和保存映记

用户在创建页填写标题、时间地点和正文，选择样例照片或导入本地照片。保存时应用生成稳定映记对象，写入本地存储，并更新首页、全部映记和详情页。

导入图片继续使用 `FileReader.readAsDataURL()`，避免保存临时 `blob:` 地址。

### 管理档案

全部映记页新增管理能力：

- 编辑映记
- 删除映记
- 收藏/取消收藏
- 添加和移除标签
- 按年份、国家、城市、收藏状态、标签筛选
- 关键词搜索标题、地点、正文、标签和路线

删除操作需要二次确认，避免误删。

### 导入导出

个人档案支持导出 JSON 文件。导入时先校验版本和数据结构，再展示导入摘要，例如新增数量、重复数量、可能覆盖数量。导入默认合并，不默认覆盖已有映记。

重复判断优先使用 `id`；没有 `id` 时可以使用标题、日期、城市和正文片段组成的弱匹配。

### 恢复和降级

如果本地存储损坏或版本不认识，应用应保留种子数据，并给出可理解的状态提示，而不是白屏。

如果导入文件无效，提示用户文件格式不匹配，不修改现有档案。

## 测试策略

保留现有两类测试，并逐步增强。

1. 静态结构测试：确认关键屏幕、按钮、数据入口和样式存在。
2. 浏览器流程测试：覆盖真实用户路径。
3. 纯函数测试：在模块拆分后覆盖数据模型、筛选、导入合并、版本迁移。

优先新增的回归测试：

- 创建映记后首页和全部映记同步更新。
- 导出 JSON 后重新导入能恢复映记。
- 删除映记不会删除种子数据。
- 标签和收藏筛选结果正确。
- localStorage 损坏时应用不白屏。

## 分阶段计划

### 阶段 1：边界整理

把 `app.js` 拆分到 `src/`，保持行为不变。`index.html` 改为加载模块入口。现有测试必须继续通过。

### 阶段 2：数据模型和存储升级

引入版本化本地存储对象，增加读取旧数据的迁移逻辑。确保当前已保存映记不丢失。

### 阶段 3：档案管理能力

实现编辑、删除、收藏、标签和更完整筛选。优先让全部映记页成为真正的档案管理中心。

### 阶段 4：导入导出

实现导出 JSON、导入 JSON、导入摘要和合并策略。补齐损坏文件和重复数据测试。

### 阶段 5：公开展示完善

更新 README，补截图和 GitHub Pages 部署说明。必要时增加标准 `package.json`，让外部用户能一条命令运行测试。

## 验收标准

1. 用户可以创建、编辑、删除、收藏和筛选映记。
2. 用户可以导出完整档案 JSON，并在清空本地存储后导入恢复。
3. 本地存储损坏不会导致应用白屏。
4. 现有视觉风格和主要页面结构保持稳定。
5. 关键流程有自动化测试覆盖。
6. 项目仍可直接打开 `index.html` 运行。

## 风险

1. data URL 图片会让 localStorage 体积快速变大。短期接受，后续可增加图片压缩或 IndexedDB。
2. 模块拆分可能破坏现有交互。必须先锁定浏览器回归测试，再逐步迁移。
3. 导入合并策略如果太激进，可能误判重复。默认合并、不覆盖，是更稳的选择。
4. 没有后端意味着跨设备同步不解决，这是本阶段的明确边界。
